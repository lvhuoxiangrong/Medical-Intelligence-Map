STEP 01 论证构建 · 从三类原始资料到结构化论证

指南、文献、社交评论，如何被抽成一条条「论证」

三类资料形态差异巨大，各自走专用处理路径；最终由源文本解析 → 知识解析 → 论证构建三个智能体接力，输出结构化的临床论证——一条完整证据链与推理，而不是一段文字。

PHASE 1

STEP 02 论证融合 · 从分散论证到流程树知识图谱

论证如何变成知识图谱

每个论证的字段被映射为图谱节点，显示关系直接连边，隐含关系经发现 → 挖掘 → 验证后入库；共用实体让多份论证自动融合。图谱长成一棵棵诊疗流程树的样子，而不是「一堆实体 + 关系」。

流程树图谱 · 治疗启动场景
节点类型分色 · 条件边带人群属性 · 论据挂载可开关

边条件边：分支的核心机制

同一节点按适用人群属性指向不同下游。边上的属性是结构化区间，代码直接计算匹配、无需 LLM 介入，遍历时按患者属性自然形成分支。

{ "eGFR": [25, 60), "HbA1c": [7, 9), "BMI": null, "合并疾病": { "CKD" } }

证论据挂载：每个决策都有依据

药物、推荐动作、监测计划等实体节点，都挂载研究报告 / 指南条目 / 患者体验 / 顾虑 / 偏好等论据（支撑 / 攻击 / 中立），检索时一并拉取——零幻觉，可追溯。

溯溯源：节点可追回原始资料

每个节点记录来源论证 ID（如 GL-042）、论证类型与来源名称（如 ADA Standards of Care 2025），决策的每一步都能解释。

证据校验：四步验证 + 客观打分

每条隐含关系都要通过验证，再按保留价值决定去向。

  • 因果预判 · 仅因果解释类型，不合理直接丢弃 LLM ×1
  • 内部路径验证 · 图谱内是否已存在该路径 结构化匹配 0 次 LLM
  • 外部证据验证 · PubMed 等外部数据库检索 每路径 LLM ×1
  • 评论聚合验证 · 真实世界支持率
  • 研究价值评估 · 是否值得保留
V = 0.40 × R临床影响 + 0.20 × S严重性 + 0.40 × F研究可行性（基于 PubMed / FAERS / GBD 权威数据）
V ≥ 0.7高优先级 · 保留为研究线索
0.5 ≤ V < 0.7中优先级 · 保留
V < 0.5低优先级 · 丢弃

STEP 04 应用反馈 · 把使用中的问题回灌给知识库

应用过程中发现的每一个问题，都回流成图谱的进化

应用反馈智能体只读图谱、不直接改图谱。它把应用中发现的问题写成反馈事件流，由知识进化智能体接收执行入库与更新——消费 → 发现 → 进化 → 再消费，形成自学习闭环。

自学习：对话进行中（即时）

  • 新临床信息 · 加入当前会话证据，触发新一轮推理
  • 新体验反馈 · 作为体验类论据加入，触发新一轮辩论
  • 医生纠正 · 当前辩论标注否决，同时进入「待入库队列」
  • 医生补充 · 作为新论据加入当前辩论，同时入队

自学习：对话结束后（统一入库）

  • 患者体验 → 「患者体验」事件 → 知识进化入库
  • 医生纠错 / 补充 → 「纠错 / 新增」事件 → 更新或走新增入库流程
  • 多轮辩论无法收敛 → 「研究线索」事件 → 入线索库待跟进
  • 证据链缺口 → 「新隐含关系候选」事件 → 证据校验去验证
